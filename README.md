# NHT Fitness

NHT Fitness is a privacy-conscious Android fitness tracker for training, nutrition, body metrics, hydration, and personal-care routines. The Android application ID remains `com.aegisfit.app` so the existing Firebase Android registration and existing installs continue to work.

## First-time setup

1. Open the Firebase project referenced by `app/google-services.json`.
2. In **Authentication → Sign-in method**, enable **Email/Password**. If this provider is disabled, Firebase returns `CONFIGURATION_NOT_FOUND` or `OPERATION_NOT_ALLOWED`; the app now shows a specific setup message instead of a generic internal error.
3. Create a Cloud Firestore database, then deploy the included owner-only rules:

   ```bash
   firebase deploy --only firestore:rules
   ```

4. If the Firebase Android app was recreated, download its new `google-services.json` and replace the file in `app/`. Its package name must be `com.aegisfit.app`.
5. Copy `local.properties.example` to `local.properties`, keep the Android SDK entry generated by Android Studio, and optionally set `USDA_API_KEY`.

Open Food Facts works without a key. USDA results are simply skipped when `USDA_API_KEY` is blank. A key embedded in a mobile app can be extracted; for a public production release, put USDA access behind a rate-limited backend instead of treating the app value as a secret.

## Build and test

Use JDK 17, then run:

```bash
./gradlew test assembleDebug
```

The project limits Gradle memory and worker concurrency because earlier builds contained JVM and Kotlin daemon out-of-memory crash logs. If Android Studio supplies a different Gradle JDK, select JDK 17 in its Gradle settings.

## Food search behavior

- Typing searches the bundled on-device catalogue immediately; it never calls an API per keystroke.
- **Search online** is explicit and requires at least three characters.
- Successful queries are cached for seven days and empty queries for one day.
- Retrieved foods are stored in Room and remain searchable offline.
- Open Food Facts and optional USDA requests are limited to 20 results each, deduplicated, validated, and capped before storage.
- Serving-size nutrition is calculated from each food's actual default serving weight rather than assuming every serving is 100 g.

## Security and stability notes

- Firestore rules restrict profiles and logs to the authenticated owner.
- Clear-text network traffic, device backup, unnecessary storage/camera permissions, and unsolicited notification permissions are disabled.
- Login and password-reset errors are mapped to safe user-facing messages while detailed exceptions stay in Logcat.
- Cloud restore validates types and ranges and skips an individual malformed legacy log instead of failing the entire login.
- Background sync only runs for a signed-in user with network connectivity and has bounded retries.
- Legacy database migrations preserve version 6 data; much older unsupported local schemas are recreated.

Before releasing, use separate Firebase projects for development and production, restrict the Firebase API key to the required APIs/application, enable Firebase App Check where appropriate, and run a release build with code shrinking after testing any reflection-dependent libraries.
